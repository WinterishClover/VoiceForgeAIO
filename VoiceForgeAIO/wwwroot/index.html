Help & getting started

What this tool does

VoiceForge AIO turns a spreadsheet of dialogue lines into finished Skyrim voice assets. Point it at a CSV of lines, tell it which TTS voice each character uses, and it generates the audio — optionally also building the .lip file for facial animation and packaging everything into Bethesda's .fuz format, ready to drop straight into your mod's Sound\Voice folder.

Easiest start: read the plugin directly (no xEdit, no CSV)

Open Plugin Dialogue. VoiceForge AIO finds your Skyrim Data folder (or you point it there; if you use Mod Organizer, also give it the mods folder), lists your plugins, and reads the one you pick — every voiced line, with the speaker's VoiceType worked out the same way the xEdit scripts do it (the line's Speaker, then its voice-type, alias and ID conditions, then the quest's; scenes use their actor alias). Lines are grouped by VoiceType. Click Add missing VoiceTypes to Voice Mapping, pick a provider and voice for each, then Generate audio. Files are named the way the game expects (Quest_Topic_FormID_1) and saved under your mod's Sound\Voice\YourMod.esp\<VoiceType> folder. Voice types listed as Unknown have no speaker the plugin can resolve (player lines, for example) and start unticked. You can still Export as CSV, and the CSV route below keeps working.

1. Add your API keys

Open Settings from the sidebar and paste in the API key for whichever provider(s) you plan to use — you don't need all of them, just the ones you're actually using. OmniVoice and Qwen3-TTS run on your own computer and need no key (see "Local voices" below). MiniMax additionally needs a Group ID from its dashboard, separate from the API key. Click Show keys if you want to double-check what you typed, then Save Settings.

2. Build your Voice Mapping

This is the heart of the tool: it tells VoiceForge AIO which actual provider voice to use for each character. Skyrim VoiceType names (like "Kaylin" or "Eldis") don't mean anything to a TTS provider, so you map each one once:

  1. Click Get Available Voices — this pulls the full voice list from every provider you've added a key for.
  2. Click Add Row, type the VoiceType name (must match your CSV's VoiceType column exactly), pick a Provider, then pick the Voice for it.
  3. Repeat for every character, then click Save Mapping. This is saved permanently — you only do this once per character, ever.

You can also Export CSV to share a mapping with someone else working on the same mod, or Import CSV to load one they sent you.

3. Try a line with Single Line

Good for quickly testing a voice before committing to a full batch. Pick a provider, click Load voices to fetch its voices, choose a model and voice, type some text and click Generate audio. The result plays right away and appears in a player below; Show in folder opens where it was saved (Documents\VoiceForgeAIO\Samples unless you chose a folder).

4. Run a full batch

Your CSV needs exactly three columns, no header row:

EditorID,VoiceType,"Line text"

Point Generate at that file and at your mod's Voice folder (e.g. ...\Data\Sound\Voice\YourMod.esp) — VoiceForge AIO creates a subfolder per VoiceType automatically. Already- generated files are skipped on a re-run unless you check Overwrite existing files, so it's always safe to stop and resume a batch.

Local voices (OmniVoice and Qwen3-TTS)

These two providers run on your own graphics card: free, no key, nothing leaves your computer. Open the Local Voices page, give each one the Python of its own environment (optionally run inside WSL), click Check the install, then make voices — described in words, cloned from a 3–10 second recording, or (Qwen3-TTS) a built-in speaker — and use Hear sample to audition them. In Voice Mapping pick OmniVoice (local) or Qwen3-TTS (local) and click Get Available Voices to choose one of your voices. The model is loaded on the first line and unloaded after the idle time you set. Because voices live on your computer, an exported mapping CSV that uses them only works on the machine that made them.

5. LIP and FUZ generation (optional)

Check Generate .lip files to also build facial animation data for each line — this needs FaceFXWrapper.exe and FonixData.cdf set in Settings first (neither is bundled; FonixData.cdf usually lives under Skyrim SE's Tools\LipGen\LipGenerator folder, or comes from the Creation Kit).

Once LIP is on, Generate .fuz files becomes available — this packages the WAV and LIP together into Skyrim's native .fuz format, using xWMAEncode.exe and LipFuzer.exe (also set in Settings). A .fuz needs both a WAV and a LIP to exist, which is why this option stays locked until LIP generation is checked.

Troubleshooting tips

  • A provider fails with a rate-limit error: lower the Concurrency setting on the Generate page, or just re-run the batch — already-completed lines are skipped automatically.
  • LIP generation fails to open a file: this is usually antivirus briefly locking a freshly-written WAV; the tool already retries automatically, but if it persists, try adding an antivirus exclusion for your mod's output folder.
  • A voice doesn't show up after Get Available Voices: double-check the API key for that provider is saved in Settings, and that the key has the right permissions on the provider's dashboard.
  • Check the log panel on the right — every operation reports there, including the exact error text from whichever provider or tool failed.
